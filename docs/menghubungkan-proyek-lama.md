# Menghubungkan dengan Proyek Lama (Opsional)

Jika kamu punya proyek ETL/dashboard sebelumnya, jangan mengklaim sebagai
karya sendiri tanpa modifikasi. Dua opsi yang aman:

## Opsi A - Jadikan proyek ini portofolio utama

Cukup satu repo yang kuat. Ini pilihan yang disarankan untuk melamar posisi
Data Quality Assurance karena fokusnya jelas dan bisa dijelaskan dalam 1 menit.

## Opsi B - Fork dan perluas proyek lama dengan kredit

Jika ingin proyek kedua, lakukan ini:

1. Cantumkan sumber asli di README: "Base project: <link repo asli>, MIT/Apache
   license". Jangan hapus atribusi.
2. Tambahkan kontribusi nyata yang bisa kamu jelaskan, misalnya:
   - validasi data sebelum load (null, duplikat, range);
   - tabel quarantine untuk baris gagal;
   - halaman Data Quality di dashboard;
   - test untuk fungsi transformasi;
   - README baru yang menjelaskan arsitektur dan trade-off.
3. Tulis bagian **"Apa yang saya ubah"** dengan daftar perubahan spesifik.
4. Siapkan jawaban interview: "bagian mana yang saya kerjakan" dan "kenapa
   saya mengubah desain aslinya".

## Yang harus dihindari

- Mengganti nama penulis tanpa kontribusi.
- Menghapus file LICENSE atau riwayat asli.
- Mengklaim arsitektur orang lain sebagai desain sendiri.
- Menaruh dua repo yang isinya hampir sama; pilih satu yang paling kuat.

## Kalimat aman di CV

```text
Extended an open-source ETL project (Apache-2.0) by adding data validation,
quarantine handling, and a data quality dashboard.
```
